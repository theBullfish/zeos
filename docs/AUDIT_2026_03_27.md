# Zeos Comprehensive Audit — 2026-03-27

> Every successful OS got a thousand small things right.
> Every failed OS had a genius idea and missed a hundred of them.

This document catalogs every gap between Zeos's current state and production-grade.
Organized by severity, then by subsystem. Each item explains **what**, **why it matters**,
and **what happens if you skip it** (with real-world casualties where applicable).

## PART 1: THE CRITICAL PATH (Ship-Stoppers)

### 1.1 Kernel Boots on Borrowed Time

**The kernel runs from memory it thinks is free.**
`pmm_init` does not mark the kernel's own `.text`, `.data`, `.bss`, or `.rodata` as used.
Nor does it mark `EfiLoaderCode`/`EfiLoaderData` regions. The PMM will hand out pages
containing the running kernel to the next `pmm_alloc` caller. Silent corruption, then crash.

- **Fix**: Walk the UEFI memory map, mark all `EfiLoaderCode`, `EfiLoaderData`, and
  `EfiBootServicesCode/Data` regions as reserved. Also reserve the kernel image range
  (link-time symbols `__kernel_start` / `__kernel_end`).
- **Skipping it**: Random crashes after ~50 allocations. Impossible to reproduce.

**No GDT. No TSS.**
The kernel uses UEFI's GDT, which lives in boot-services memory (now freed).
Any interrupt that loads a segment selector references a potentially-overwritten GDT.
Triple fault. No TSS means no IST stacks, no ring-3 transitions, no I/O permission bitmap.

- **Fix**: Create a minimal GDT (null, kernel code64, kernel data, user code64, user data, TSS)
  and load it before `idt_init`.
- **Skipping it**: Works until someone allocates over the old GDT. Then: instant triple fault
  with no diagnostic.

**No CPU exception handlers (vectors 0-31).**
Divide-by-zero, page fault, double fault, GPF, invalid opcode — all triple-fault the machine
with zero diagnostic output. This is the single most important missing feature.

- **Fix**: Register handlers for at least vectors 0, 6, 8, 13, 14 (with IST stack for #DF).
  Print register dump + stack trace on fault. Halt.
- **Skipping it**: Every bug manifests as "machine rebooted." You will never debug anything
  on real hardware.
- **Historical**: Mars Pathfinder survived because VxWorks had a watchdog that caught the
  priority inversion reset loop. Without exception handlers, Zeos cannot even detect its own crashes.

**No kernel stack.**
The boot code runs on UEFI's stack — size unknown, location unknown, in memory the PMM
considers free. A deep call chain (shell -> vault_write -> pmm_alloc -> ...) may silently
overwrite PMM bitmap or heap metadata.

- **Fix**: Allocate a dedicated kernel stack (16KB minimum) in `pmm_init`, set RSP after
  `vmm_init`. Mark the stack pages as reserved.
- **Skipping it**: Stack corruption that manifests as heap corruption. The worst kind of bug.

### 1.2 Memory Management Will Eat Itself

**Identity mapping is the only addressing mode.**
The entire kernel assumes `physical == virtual`. The heap stores raw physical pointers.
The PMM bitmap is accessed via physical address. The moment you unmap the identity
mapping (required for security, required for user-space isolation), every pointer in
the PMM and heap breaks.

- **Fix**: Implement `phys_to_virt()` / `virt_to_phys()` macros (Linux's `__va()` / `__pa()`).
  Use them consistently. This is a large refactor but it must happen before any address
  space isolation is possible.
- **Skipping it**: Permanent architectural debt. You can never have separate address spaces,
  which means no process isolation, no user-space, no security boundary.

**4GB identity map is RWX everywhere.**
All 4GB mapped as 2MB huge pages, read-write-execute, no NX bit. This violates W^X
(write XOR execute), making code injection trivial from any buffer overflow.

- **Fix**: After boot, remap kernel sections with correct permissions:
  `.text` = RX, `.rodata` = R, `.data/.bss` = RW+NX, MMIO = RW+NX+UC, framebuffer = RW+NX+WC.
  Enable SMEP/SMAP in CR4.
- **Skipping it**: Any buffer overflow is automatically code execution. Every security
  researcher's first finding.

**No page fault handler.**
Without #PF (vector 14), you cannot implement: demand paging, copy-on-write, stack growth,
memory-mapped files, swap, lazy allocation, or guard pages. The VMM is structurally complete
but functionally inert.

**Bitmap allocator is O(n) per allocation, no locking.**
On your 128GB machine: 33 million frames, 4MB bitmap. Linear scan on every alloc.
No spinlock — the moment a second core is brought up, two concurrent `pmm_alloc` calls
return the same frame. Instant memory corruption.

- **Fix**: Phase 1: Add a spinlock. Phase 2: Buddy allocator (O(1) common case).
  Phase 3: Per-CPU page caches. Phase 4: NUMA zones.
- **Skipping it**: Uniprocessor only, slow under pressure. Acceptable for now if SMP is deferred.

**Heap coalescing is broken across non-adjacent expansions.**
When `kmalloc` expands the heap via `pmm_alloc_contiguous`, the new region may not be
physically adjacent to the old heap. But `coalesce` assumes adjacency — it extends a block's
size to cover the next header without checking that the memory between them belongs to the heap.
This corrupts whatever is in between.

- **Fix**: Check physical adjacency before merging: `(char*)block + HEADER_SIZE + block->size == block->next`.
- **Skipping it**: Heap corruption after the first non-adjacent expansion. Manifests as
  random `kfree` crashes minutes later.

### 1.3 No Locking Anywhere

Not a single spinlock, mutex, or atomic operation exists in the entire kernel.
Every shared data structure — PMM bitmap, heap free list, tick counter, PCI device array,
signal chain array, VAULT superblock, network state — is a race condition the moment
a second CPU exists.

This is the #1 blocker for SMP.

- **Fix**: Start with a big kernel lock (BKL) around all shared state. Then progressively
  split into per-subsystem locks. Then lock-free structures where appropriate.
- **Skipping it**: Uniprocessor only. Your 16-core Ryzen AI MAX+ runs 1 core. The BlueField-2's
  16 ARM cores are unusable.

## PART 2: HIGH SEVERITY (Blocks Real Hardware)

### 2.1 Interrupt System is PIC-Only

**No APIC, no MSI/MSI-X.**
The 8259 PIC is legacy hardware. Modern systems require Local APIC + I/O APIC.
PCIe devices (Goya, FPGA, BlueField NIC) use MSI/MSI-X interrupts exclusively.
Without APIC: no SMP interrupt routing, no PCIe interrupts, no per-CPU timers.

The Goya HL-100 generates MSI interrupts for command completion. Without MSI support,
you cannot receive inference completion notifications. You are limited to polling.

- **Fix**: Parse MADT ACPI table, initialize Local APIC and I/O APIC, set up MSI/MSI-X
  capability parsing in PCI subsystem.
- **Skipping it**: All real PCIe devices are interrupt-dead. Polling-only for everything.

**No APIC timer.**
The PIT (8254) fires at 1000Hz on IRQ0 via the PIC. It's a shared resource (one per system).
The APIC timer is per-CPU, essential for SMP scheduling. Without it, you have one timer
for the whole system.

### 2.2 PCI Subsystem Gaps

**No PCI capability walking.**
PCI capabilities (MSI, MSI-X, power management, PCIe, AER, SR-IOV) are invisible.
Cannot discover device features, cannot enable MSI, cannot read PCIe link status.
The Goya driver needs capability registers to enable interrupts and DMA features.

**No BAR sizing.**
BARs are read but never sized (write-all-1s probe). Drivers cannot know how large
an MMIO region is. The Goya's multiple BARs (config, SRAM, DRAM) need proper sizing.

**No IOMMU (AMD-Vi).**
DMA from any PCIe device can read/write any physical memory. A bug in the Goya firmware,
a malicious FPGA bitstream, or a rogue USB device over Thunderbolt can read kernel memory.
Your UT3G Thunderbolt enclosure is a physical DMA attack surface.

- **Fix**: Enable AMD-Vi early (in bootloader, before any device does DMA). Program IOMMU
  page tables per-device.
- **Skipping it**: Zero device isolation. A Goya DMA bug corrupts the kernel. A Thunderbolt
  attack reads your encryption keys.
- **Historical**: December 2025 — ASRock, ASUS, Gigabyte, MSI firmware failed to initialize
  IOMMU during boot, allowing pre-OS DMA attacks via Thunderbolt.

**Subordinate bus configuration not handled.**
PCI-PCI bridges need secondary/subordinate bus number configuration. Without it,
devices behind bridges (common in PCIe topologies) may be invisible if firmware
didn't configure them.

### 2.3 Networking is Demo-Only

**TCP has no retransmission.**
A single dropped packet = silent data loss. No RTT estimation, no RTO, no fast retransmit.

**TCP has no congestion control.**
Blasts segments at wire speed. Will overwhelm any real network link or trigger RSTs.

**No DHCP.**
Hardcoded to QEMU SLIRP addresses (10.0.2.x). Dead on any real network.

**No TLS.**
All HTTP is plaintext. In 2026, ~95% of web traffic is HTTPS. The HTTP client
is useless against real servers.

**DNS transaction ID is hardcoded `0x1234`.**
Trivially spoofable. Combined with predictable ephemeral ports, DNS poisoning
takes one packet.

**ARP cache accepts all replies unconditionally.**
Classic ARP spoofing. An attacker on the local network redirects all traffic.

**TCP receive buffer overflow ACKs data it dropped.**
When `rx_buf` is full, incoming data is truncated but the ACK advances.
The remote thinks data was received. This is silent data loss.

**Only one TCP connection at a time.**
`active_conn` is a single static pointer. Opening a second connection
overwrites the first.

### 2.4 No Real Hardware Drivers

Only virtio-net (QEMU) exists. For real hardware you need:
- **NVMe** — for disk persistence (VAULT is RAM-only)
- **XHCI (USB 3.x)** — for Coral TPU, USB keyboards on real hardware
- **E1000/RTL8168** — for real network adapters
- **AHCI/SATA** — for disk on CN60 Chromebox
- **Habana Goya** — custom PCIe driver for HL-100 command submission
- **AMD display** — for your Z13's RDNA 3.5 (UEFI GOP fallback works but is limited)

### 2.5 VAULT Has No Persistence

The filesystem is a 2MB `static uint8_t[]`. On reboot, everything is gone.
No block device abstraction, no I/O scheduler, no write-ahead log.
For a "temporal filesystem that never forgets," this is existential.

**No crash recovery.**
No journal, no CoW tree, no checksums. Interrupted write = corrupted filesystem.
Ext4's delayed allocation bug (Ubuntu Bug #317781) caused zero-length files after crash.
Btrfs had silent corruption with NOCOW compressed files during replace operations.
Without atomicity, VAULT is less crash-safe than FAT32.

**No garbage collection of old versions.**
Every write to an existing file allocates a new version inode. With 1024 total inodes,
writing to the same file ~1000 times exhausts the inode table. The "never forgets"
design means storage grows monotonically with no pruning.

## PART 3: MEDIUM SEVERITY (Breaks Under Load or Adversarial Conditions)

### 3.1 Signal Chain Engine

**No cycle detection.**
`A -> B -> A` hangs the resolve loop forever. No iteration limit, no visited-set.

**Multi-input merge is broken.**
When a node has `input_required > 1`, each upstream overwrites `dst->input` via
`sig_data_copy`. Only the last-arriving input survives. Fork-join is non-functional.

**No chain reclamation.**
32 chains max. Never freed. After 32 `zp_run` calls, all future programs fail.

**No error propagation.**
A failed node is set to `SIG_ERROR`; downstream nodes silently never fire.
No poison pill, no error signal, no way to distinguish "errored" from "not yet fired."

**`delta_history` is global, shared across chains.**
Two chains with delta nodes at the same index corrupt each other's state.

### 3.2 Z+ Interpreter

**Recursive lexer stack overflow.**
Unknown characters recurse into `lexer_token`. A string of 1000 `@` symbols
blows the stack.

**Integer overflow in number parser.**
`val = val * 10 + (d - '0')` wraps silently on numbers > INT32_MAX.

**Only int32 type.**
Despite the spec describing f32, units (cm, C, Hz), knee (proportional control),
channels, exchanges, temporal access, merge policies, and more.
The implemented language is approximately 5% of the specified language.

### 3.3 Timer Calibration

**TSC calibration hardcodes 1000Hz assumption.**
`tsc_freq = elapsed_tsc * 20` is literally `elapsed_tsc * (1000/50)`.
If `timer_init` is called with a different frequency, calibration produces
wrong values. Every `timer_wait_ms` is off by a proportional factor.

**No TSC invariant check.**
Not all CPUs have invariant TSC. On older CPUs, TSC rate changes with
C-states/P-states. Should check `CPUID.80000007H:EDX[8]`.

**No wall clock.**
No RTC reading, no calendar time, no NTP. Cannot timestamp anything.

### 3.4 Framebuffer and UI

**Assumes 32-bit ARGB pixel format.**
`pixel_format` is stored but never checked. On BGR or 24-bit firmware,
colors are garbled.

**No double buffering.**
Screen tearing guaranteed during any animation.

**Byte-by-byte scroll.**
`fb_scroll` copies the entire framebuffer pixel by pixel. On 1920x1080,
that's 8MB of single-byte copies. Visibly slow.

**Spring animation system is never driven.**
`anim_tick(dt)` is defined but never called — the shell blocks on
`keyboard_getc()`. Animations are defined but never run.

### 3.5 Keyboard and Serial

**PS/2 only, no USB HID.**
On modern hardware without PS/2 (or BIOS USB legacy), keyboard is dead.

**No Ctrl, Alt, arrow keys, function keys.**
Only Shift and CapsLock tracked. Cannot Ctrl+C to interrupt.

**Serial is output-only, single-port, polled.**
No receive, no flow control, no COM2-4. Hangs forever if UART breaks.

## PART 4: THE LITTLE THINGS THAT SEPARATE REAL FROM TOY

### 4.2 Memory

### 4.6 Edge Cases Real OSes Handle

| Item | What Goes Wrong Without It |
|------|---------------------------|
| **Leap seconds** | 2012: Linux livelock took out Reddit, Qantas, LinkedIn, Mozilla |
| **Y2038** | Signed 32-bit `time_t` overflows Jan 19, 2038. Use 64-bit from day 1 |
| **Unicode normalization** | Two files with visually identical names, different bytes. Pick NFC, enforce at FS layer |
| **Endianness** | Model weights serialized on x86 corrupt on ARM if no explicit format |
| **Timezone handling** | Store TAI internally. Convert to UTC at API boundary. Eliminates leap second class entirely |
| **Locale** | Number formatting, decimal separators, text sorting — matters for any user-facing output |
| **CMOS battery death** | RTC returns 2000-01-01. Timestamps on all files are wrong. NTP fallback needed |

### 4.7 Accelerator-Specific Details

| Item | Why It Matters |
|------|----------------|
| **DMA cache coherency** | CPU cache not flushed before Goya DMA = stale data read. Silent inference corruption |
| **Memory pinning** | Goya DMA to a reclaimed page = write to wrong physical address |
| **Interrupt coalescing** | Per-inference IRQ drowns CPU at high throughput. Need adaptive coalescing |
| **Command queue per-engine** | Goya has MME, TPC, DMA engines. Pipeline them, don't serialize |
| **Fence/barrier sync** | Cross-device synchronization (CPU->Goya->FPGA). The single most critical design decision |
| **Accelerator crash dump** | Goya hang = capture TPC registers, DMA descriptors, command queue. Otherwise undebuggable |
| **Per-device thermal monitoring** | Goya over UT3G has no cooling feedback. Need watchdog per accelerator |
| **Hotplug** | UT3G USB4 cable disconnect mid-inference. Must cancel DMA, notify chain, clean up |
| **Bounce buffers** | 32-bit DMA device + memory above 4GB = need bounce buffer or IOMMU |
| **Memory pinning budget** | Pinning GB of model weights starves the kernel. Need per-device limits |

## APPENDIX: Historical Casualties

| OS | Genius Idea | What Killed It |
|----|-------------|----------------|
| **BeOS** | Pervasive multithreading, real-time media | Microsoft OEM threats; no ecosystem |
| **OS/2** | Better DOS than DOS, better Windows than Windows | IBM couldn't seed developer ecosystem; "without drivers, users wouldn't adopt" |
| **Plan 9** | Everything is a file (network, graphics, everything) | Too alien for existing software to port |
| **Hurd** | Pure microkernel, everything in userspace | Mach IPC overhead made it unusable |
| **Taos/Elate** | Virtual processor bytecode, heterogeneous JIT | Company folded — nobody knew it existed |
| **Inferno** | Limbo language, Styx protocol, cross-platform | Never achieved commercial traction |
| **TempleOS** | Ring-0 only, 640x480x16, 64-bit HolyC JIT | One-person project, no ecosystem, no networking |
| **ReactOS** | Open-source Windows NT clone | ACPI bugs, driver compatibility, glacial progress |
| **Haiku** | BeOS revival | Package management struggles, small team |

**The meta-lesson**: Technology does not win. Ecosystem wins. The migration path from
existing ML workflows to Zeos must be: "your ONNX model runs unchanged, only the
runtime is different." If developers must rewrite anything, Zeos follows Taos into obscurity.
